# Decisions

Short records of choices that shape the build. Newest last.

| ID | Decision | Why | Revisit when |
|---|---|---|---|
| D01 | Run natively (`make dev`), no Docker during development | Faster reloads, nothing to start, clearer errors. Containers add nothing visible to the demo | Packaging for reviewers (P12) |
| D02 | SQLite through SQLAlchemy 2 + Alembic | Zero setup. Nothing SQLite specific outside connection pragmas, so Postgres is a URL change | Concurrent workers or multi-user (production: Postgres) |
| D03 | Files stored on disk by sha256 under `var/blobs` | Natural dedupe, same contract as S3 keyed by hash | Production (S3 with Object Lock + KMS) |
| D04 | Python 3.13, uv, ruff, pyright strict, pytest with warnings as errors | Catch problems at the edge, not in the demo | n/a |
| D05 | Next.js 16.4 App Router, Tailwind 4, design tokens as CSS variables | Tokens drive both themes from one place. Theme follows the OS unless chosen explicitly, applied before first paint | n/a |
| D06 | Fonts: Public Sans (UI), Overpass (display), Overpass Mono (identifiers), self-hosted via next/font | Highway-signage lineage fits the domain. Mono makes O vs 0 unambiguous in license numbers | n/a |
| D07 | CI runs lint, strict types, tests, a production build and a hardcode guard | The guard proves the pipeline is not tuned to the sample packet | n/a |
| D08 | Idempotency key is the Message-ID; the raw sha256 only when there is no Message-ID | Mail servers re-encode messages in transit, so the same email can arrive with different bytes. Message-ID is the sender's identity for the message | Follow-up emails (In-Reply-To) should attach to the open submission (design only) |
| D09 | File type is sniffed from bytes. Filenames and declared MIME types are kept as untrusted hints only | The brief warns names are misleading. Sniffing decides how to open a file; business document type is decided later from content | n/a |
| D10 | Archives are read in memory and members stored by hash, never extracted to disk by name. Limits on depth, count, per-file size, total size and compression ratio | Path traversal is impossible by construction; zip bombs are capped by actual bytes read, not declared sizes | n/a |
| D11 | Nothing is dropped. Every file ends as accepted, duplicate, expanded or rejected with a reason, and each outcome is an audit event | An underwriter must be able to see that an attachment arrived, even when Lane could not read it | n/a |
| D12 | Audit log is hash-chained with a unique previous-hash column | Edits and deletions break verification; two writers cannot fork the chain | Production: Postgres advisory lock or a ledger table, periodic anchoring of the tip hash |
| D13 | PyMuPDF 1.28 behind a typed adapter (`documents/pdf.py`), the only module with relaxed type checks | 2.0 pulls in an ONNX layout model we do not need. The adapter keeps strict typing elsewhere and makes the engine swappable. PyMuPDF is AGPL: production would buy a commercial license or swap in pypdfium2 behind the same adapter | Licensing review before production |
| D14 | Triage is physical only: text, scan, photo, sheet, email body, plus a quality band. Business document type is decided later from content | Keeps "how to read it" separate from "what it is". A misnamed file still gets read correctly | n/a |
| D15 | Quality measures: sharpness = 99th percentile Laplacian on ink edges (not Laplacian variance), colorfulness for photo vs scan, projection profiles for skew and sideways pages. Thresholds live in settings and were set by profiling the packet: clean scans ~200+, blurred ~20, phone photos ~50 | Laplacian variance penalizes sparse but sharp pages. All thresholds are config, not code | Calibrate on more packets |
| D16 | Pipeline runner: ordered steps, each recorded and committed with status, duration and summary; required steps stop the run, optional ones degrade it; transient errors retry with backoff; steps skip work already done at the current version | Visible progress and failure states without a workflow cluster. Same contract as Temporal activities | Production: Temporal |
| D17 | Derived artifacts (page renders, thumbnails, word boxes, sheet grids) are content-addressed blobs served with immutable caching | Same dedupe and integrity as inputs; the UI can cache aggressively | n/a |
| D18 | One LLM gateway: typed request, structured output validated by Pydantic, every call recorded (model, prompt version and hash, tokens, cost, latency, request id), outputs cached by (model, effort, prompt hash, schema, input hash) | Replayable runs, honest cost reporting, and reruns that cost nothing. A bad answer or a failed call is one recorded failure, never a crashed batch | Production: same interface over Bedrock or Azure |
| D19 | Models per task are settings: Haiku 5.5 classifies (effort low), Sonnet 5.5 will extract, Opus 5.5 will analyze. Server-side refusal fallback (`fallbacks: "default"`) is on for Sonnet and Opus; Haiku has none | Matches the plan's cost/quality split; one sample run of 33 page classifications cost $0.018 | Re-measure on more packets |
| D20 | Classification is per page, then deterministic splitting: a new document starts on a header, a type change or a different identifier; same-type worksheets of one workbook stay together | The MVR bundle becomes 6 MVRs and 2 license photos without any packet-specific rule; the split logic is testable without a model | n/a |
| D21 | Keyword signals check the model on pages with text. Agreement raises confidence, related types (application vs its driver tab) cap at medium, disagreement goes to review. Without a model, text pages fall back to keywords and image pages wait for review | Two independent signals make confidence mean something, and the run degrades instead of failing | Add OCR text for scans (P4) so they get a second signal |
| D22 | Filenames are recorded as a hint and compared after classification; a file "mismatches" when no document inside it is what the name suggests | Shows the brief's misnamed-file case explicitly. Verified: shuffling every filename produced identical documents (0 differences by content hash) | n/a |
| D23 | Supersession: same type, same normalized identifier, same period; newest document date is active, older copies superseded; undated or same-dated copies go to review | Older MVRs and photos of renewed licenses are history, not conflicts | n/a |
| D24 | Tests never call a model: an empty key overrides .env, and tests that need model output inject a scripted transport | No surprise spend, deterministic CI | n/a |
| D25 | Extraction runs on Haiku 5.5 by default. A document that fails its checks is marked "needs escalation" with the reasons and an estimated cost; nothing goes to Sonnet 5.5 until a person approves (once per run: `make escalate` or the API). Approved documents keep using Sonnet on later runs | Cheap by default, careful where the evidence says so, and spend is always a human decision. Sample packet: 22 documents read for about $0.05 on Haiku, 53 of 53 checks pass, no escalation needed |
| D26 | The model copies values verbatim with a quote and page; code normalizes (money, numbers, percentages, dates) and finds each value on the page's word boxes. Worksheets: the model returns cell references only, and code reads the cell | Values stay checkable against the source; spreadsheet values cannot be misread or invented. Sample: 99.8% of text-PDF values found on their page |
| D27 | Arithmetic self-checks are the second reading for scans: IFTA rows against printed totals and tax = gallons × rate, loss-run lines against claim and term totals, shares adding to 100% | Catches misreads without a second OCR engine. Building them surfaced a real IFTA rule: surcharge lines are taxed on taxable gallons and excluded from gallon totals |
| D28 | Structured output with a simplified wire schema: every field required, nullable strings sent as plain strings with "" meaning "not shown", mapped back to None only where the model allows None. If the API reports the schema's grammar is too large (applications, quote forms), the same request is retried with the schema in the prompt; strict Pydantic validation runs either way | Large insurance forms exceed the constrained decoder's grammar limit. Validation, not the decoder, is the safety net |
| D29 | Document ids are stable (hash of submission, file and first page) and classification upserts instead of recreating, so facts and escalation approvals survive reruns | A rerun must not lose a person's approval or break evidence links |
| D30 | Scanned pages have no word boxes yet: their facts point at the page, not a box, and their confidence comes from the arithmetic checks | OCR boxes for scans are optional polish (plan P9); the evidence is still the page and the quote |
| D31 | Resolution is an evidence board: every document's value for every attribute is a candidate with its sources and fact ids. Agreement merges; a newer official record supersedes an older copy (shown, not queued); anything else is a conflict with all candidates and an authority hint. Nothing is picked silently | Matches the plan's principles 3.1-3.8; a person can always see why a value is what it is |
| D32 | Comparison is by meaning, not text: company names ignore entity suffixes and insurer boilerplate, person names match by word sets with middle names allowed, money/dates/phones/IDs normalize first, entity form is compared separately from the name | Formatting differences never become conflicts. On the sample: 13 conflicts, all real, none from formatting |
| D33 | Entities are matched across documents by license number then name plus date of birth (drivers), VIN then one-character VIN typos (vehicles), and start dates within ten days (coverage terms by line) | Ties a claim's driver and truck to the schedule, or shows that they are not on it |
| D34 | Derived checks that need the whole submission: owner listed as a driver vs "owner drives: no"; vehicles in claims vs "no unlisted vehicles"; stated farthest territory vs IFTA miles (state-center distances); claimed years of prior insurance vs documented terms; physical damage claimed vs loss runs | These are the conflicts no single document shows; each derived candidate names the documents it rests on |
| D35 | Mappings reconcile differently shaped forms: commodity lists grouped into cargo classes, "State minimum" UM limits against a small table of state minimums (CA 30/60 since 2025-01-01) | Taxonomy differences are not conflicts (plan 3.7). States not in the table stay unreconciled rather than guessed |
| D36 | Missing information is listed as facts in an underwriter's words (FEIN, garaging, signature, stated values, invalid VINs, MVRs, unlisted drivers and units, loss runs per listed term, partial letters, coverage gaps, IFTA quarters). Whether an item blocks a quote is the rules engine's call | Keeps "what is missing" separate from "does it matter under this guideline" |
| D37 | OCR with RapidOCR (PP-OCR models on ONNX Runtime) for every scan and photo, behind a typed adapter (`documents/ocr.py`). Models ship in the pip package, so nothing is installed system-wide. Supersedes D30 | Scans get word boxes like digital PDFs: highlights in the evidence view, keyword signals for classification, and a fallback when no model is available. Production can swap in Textract or Azure Document Intelligence behind the same function |
| D38 | Dual read: the vision model reads the image alone (OCR text is deliberately not sent), then each value it read is looked up in the OCR words. Confirmed values get a box and high confidence; unconfirmed ones stay medium with the reason. Documents without arithmetic checks (license cards) need OCR to confirm at least 60% of values, or they wait for escalation | Two independent readings make confidence mean something. Sample: OCR confirmed 99.7% of image-read values |
| D39 | OCR matching folds look-alike characters (I/l/1, O/0) as a fuzzy match, never an exact one | OCR read "Iowa" as "lowa" on every IFTA page; folding confirms it without overstating certainty |
| D40 | The guideline is a versioned YAML ruleset (id, section, verbatim quote, predicate, decline flag, parameters) over a registry of typed predicates. Rules read resolved fields only, never model output; the file's sha256 is stored with every decision | Underwriters can read and change thresholds without code; every decision names the exact ruleset it ran under |
| D41 | Outcomes: pass, flag (a note), refer (underwriter review), decline (outside the program), unknown (needs outside data, e.g. SAFER, premium), n/a. The worst outcome sets the recommendation; unknown counts as refer, never as pass | "Cannot tell" is never treated as "fine" |
| D42 | Sensitivity: a rule that read a conflicted field is re-run under each candidate value. A conflict that changes the outcome blocks the rule and is linked to it; a decline that rests on one becomes "refer, potential decline". A rule left unknown by a conflict takes the outcome every combination agrees on | Declines only on confirmed facts; conflicts that do not matter stop holding up the file. Sample: the CDL decline depends on whether the owner drives, so it is a potential decline |
| D43 | Rules count time from the application date by default (a setting) and are re-run from the effective date; any outcome that changes is noted on the rule with the specifics | Loss-run age and IFTA quarters shift across that window; the underwriter sees both readings |
| D44 | Routing uses every power-unit count the documents support. If all counts fall on one side of the 10-unit line the route is stable; otherwise it goes to the larger team and says why | Sample: counts 4 and 5 both route to Small Fleet, so the conflict does not change routing |
| D45 | The analyst sees a brief, not documents: resolved fields, conflicts, missing items, rule results and figures computed in code (miles per unit at every unit count, out-of-state share, quarter-over-quarter change, claim reporting lag, incurred per term, load value vs cargo limit). License numbers and FEIN become tokens, dates of birth become ages, addresses and contact details are withheld, claimant names are tokenized; the token map stays on the server | Data minimization, and the model never does arithmetic. Sample brief: about 21k tokens, no raw identifier in it |
| D46 | Every brief item has a short citation id (F field, E entity, C conflict, M missing, R:rule, X figure) that maps to fact and document ids. Code checks every finding: no valid citation, a hypothesis without a basis, or language that approves, binds or declines means rejection. One retry with the problems listed; whatever still fails is dropped and recorded | AI explains and never decides, and every claim opens its evidence. Summary citations become numbered footnotes |
| D47 | The analyst step is optional: no key, a timeout or a bad answer marks it degraded with "AI analysis unavailable for this run. Rules and extracted data are complete." The last good analysis stays visible, labeled as not from this run | Model failure is a visible state, never a broken page |
| D48 | Finding ids are stable (submission + title), so an underwriter's accept or dismiss survives reruns. Dismissing needs a reason. Accepted recommendations join the agent request | Reviews are work; reruns must not erase them |
| D49 | The agent request is built in code from rules with a `request` (grouped before quote, before binding, for your information), uncovered missing items by category, open conflicts not already asked elsewhere, and accepted recommendations. `covers`, `request_key` and `request_details` live in the ruleset YAML so duplicates are removed without code | Plain, specific, deduplicated asks; wording changes need no deploy |
| D50 | The draft email: the model (Sonnet) writes only the opening, closing and one sentence per item headline; code appends the specifics (names, dates, VINs) under each item, so details never reach the model and cannot be altered. Code rejects internal terms and falls back to plain wording per item; a template replaces the model when unavailable. Drafts are versioned and rebuilt only when included items change. No send endpoint exists | Never sent, never wrong on the facts |
| D51 | Gold set and scorer: `evals/gold/sample_packet.yaml` written from the source documents, scored by `make eval` into `evals/report/`. Building it found four real gaps, fixed: percent-formatted cells read as 1 instead of 100%, the blank historical premium table, the Inc/LLC vs "no ownership change" conflict, and truncated question labels | Measured, not asserted. Sample: 100% on documents, splitting, supersession, 45 fields, 13 conflicts, 14 missing items, 27 rules and the route, before the analyst |
| D52 | Demo roles with HMAC-signed, expiring bearer tokens (`POST /auth/demo-login`). No token means the configured demo role (underwriter) so the prototype opens without a sign-in screen; a bad or expired token is refused. Permissions: underwriter reviews, reveals and approves spend; ops sees intake health and reprocesses but no document content; admin reads all and evals but cannot reveal. Images and event streams accept `access_token` because they cannot send headers | RBAC that is real enough to demo and test. Production: SSO (Entra ID or Okta) with the same permission checks |
| D53 | Personal data (license numbers, dates of birth, street addresses, FEIN) is masked in every API response for every role, including extracted data, fact quotes, entity keys and audit payloads. An underwriter reveals one field at a time (`POST /fields/{id}/reveal`), written to the audit chain. Page images and the agent email carry personal data by nature, so they are limited by role instead. Logs mask the same keys | Least exposure by default, with every exception recorded. One list in settings drives the analyst brief, the API and the logs |
| D54 | Live progress uses an in-process event bus with a bounded buffer per submission, streamed as Server-Sent Events: a snapshot first, then each event (pages, documents, extraction, conflicts, missing items, rules, decision), resumable with Last-Event-ID, closed shortly after the run ends | Drives the live intake view from real events, not timers. Production: Postgres LISTEN/NOTIFY or Redis streams behind the same publish and read calls |
| D55 | The OpenAPI schema is exported without a server and committed (`frontend/src/lib/api/openapi.json`); `openapi-typescript` generates the types and `openapi-fetch` gives a typed client. Operation ids are handler names. A pytest test fails when the committed schema is stale, CI regenerates the types and fails on any diff, and ESLint forbids hand-written response types in the client | The UI cannot drift from the API |
| D56 | The overview endpoint (`GET /submissions/{id}`) assembles the decision brief: route, footnoted analyst summary, blockers ordered potential decline, decline, missing documents, blocking conflicts, refer, unknown, flag, and key numbers (power units with conflict marker, drivers, 3-year incurred, open claims and reserves, annual miles, share outside the home state), each linked to its evidence | One call renders the first screen an underwriter reads |
| D57 | The UI is six views holding twelve tabs, each tab a route (`/submissions/[id]/coverage`), so every screen is linkable and the browser's back button works. Data comes through TanStack Query hooks over the generated client, keyed by submission so one invalidation refreshes a submission | Underwriters share links and switch tabs constantly; cached tabs switch instantly |
| D58 | The evidence lens is the single way to see a source: field, facts, entity or page targets, opened from any value or by focus plus E. PDF and scan pages zoom to the fact's box and draw it once; worksheets render a cell window with the cell outlined; the email body highlights the span. It overlays below 1600px and docks beside the content above | One interaction, everywhere, so "where did this come from" is always one keypress away |
| D59 | Live intake is driven only by the event stream (no timers): tiles flip to content labels, misnamed files are struck through, bundles fan out, trays fill, rules light up by id, the route sign lands. Reduced motion plays the same sequence as state changes with a polite live region. It is reviewed by replaying a recorded real run in Playwright | The one orchestrated moment shows the real pipeline, and can be reviewed without model spend |
| D60 | Screenshot review is part of the build: `make screens` captures every screen in light and dark at 1440x900, including the open lens and the live intake mid-run and done; findings are logged in docs/UX.md. Captures are regenerated, not committed | Design quality is checked the same way every time; the review found and fixed a real evidence bug |
| D61 | Driver attributes carry their own facts as evidence (the DOB cell for the date of birth), not every fact used to match the driver | Found in screenshot review: the lens opened the license cell for a date of birth |
| D62 | A guideline line that can be read more than one way is evaluated under each reading (`readings:` in the ruleset, each tied to an assumption id). If the readings disagree on a decline, the rule refers as a potential decline and names the reading that would decline. First use: "non-listed states" read as domicile (primary) and as operations by IFTA miles (A03, 5% tolerance) | The guideline's ambiguities are surfaced, not resolved silently; the same certainty logic as conflicts applies to interpretations |
| D63 | Every interpretive call has an assumption id in the ruleset; rules cite the ids they depend on, loading fails on an undefined id, and the Rules tab shows them in words. docs/ASSUMPTIONS.md explains them and docs/QUESTIONS.md asks Knight to confirm each one | The brief asks for assumptions to be called out; they are now part of the product, not only the docs |
| D64 | A person settles a conflict by choosing one of its values with a required reason. The choice is stored per field (stable ids), applied during resolution, audited, and the rules rerun synchronously; the UI shows each outcome that changed. Settled conflicts can be reopened. The agent email is marked out of date, not redrafted automatically | The minimal human-in-the-loop write path; rerunning is code only, so it is instant and free |
| D65 | The analyst asks before spending: when its answer is not cached and the estimate is above `analyze_auto_budget_usd` (default 0), it waits for an underwriter's approval, showing the estimated cost. One approval covers one run | Paid model use is a person's decision (A16), as escalation already was |
| D66 | Runs still marked running when the service starts are marked failed with "Interrupted: the service restarted…", and their submission is marked failed | A restart must never leave a screen waiting forever. Production replaces this with durable workflows that resume |
| D67 | A request without a sign-in is a read-only viewer; the demo UI signs in as underwriter explicitly. The API refuses to start outside development with the default sign-in secret. Viewers see the agent email with known license numbers and dates of birth masked | Least privilege by default; the convenience lives in the demo client, not the API |
| D68 | Text that tries to instruct a reader or a system ("ignore previous instructions", "approve this submission") is found in every page's text, including white text, and the email body. Each attempt is recorded once per page in the audit chain and shown as a banner on the brief. Patterns are settings | Injection attempts are visible even when no model runs; document text is still never treated as instructions |
| D69 | A PDF that MuPDF had to repair is flagged on every page ("The file is damaged; only the part that survived could be read"), its quality drops to degraded, and the damage is audited. If nothing readable survives, the file is unreadable | Found by the corrupt-file perturbation: a truncated loss run opened silently with its header intact |
| D70 | Perturbation suite (`make perturb`): six perturbed copies of the sample email (renamed files, rotated scans, a missing loss run, the packet sent twice, prompt injection, a corrupt PDF), each with its expected effect written beforehand in evals/perturb, checked against the unperturbed baseline. A synthetic two-truck carrier in different layouts (scripts/make_synthetic_packet.py) must come out clean | Generalization is shown on packets the system was not tuned on, not asserted |
| D71 | The gold set covers 102 fields from the hand-verified tables (license numbers, classes, policy numbers, every IFTA total), and the Evals screen says plainly that it was built by the author on the development packet | Credible measurement means stating the limits of the measure |
| D72 | A PDF application is read with its own schema whose keys match the spreadsheet application, so one resolver reads both. A loss run records the line printed in its header, used when its totals table carries no amounts | Found by the synthetic packet: a PDF application lost its FEIN, garaging, authority, start date and signature, and clean no-claims loss runs merged auto liability and cargo into one term with false conflicts. The packet's own date and IFTA quarter mistakes, which the rules correctly flagged, were fixed in the generator instead |
| D73 | Screens read typed per-kind summaries (driver, vehicle, term, history, claim, operations, IFTA quarter) computed by the API from the ruleset params and the decision anchor; components hold no guideline thresholds | The driver card had warned at 4 points in 3 years while the guideline says 6 in 3 years or 4 in 12 months. One source for every threshold |
| D74 | Driver points are counted by one helper used by the rule and the card, over events merged across a driver's MVRs with duplicates removed | Two abstracts of one license (3-year and 7-year) would otherwise count the same violation twice |
| D75 | Every response object is a declared model; a contract test rejects free-form objects except raw views and configuration (entity details, audit payload, extraction data, ruleset params, step summary). Defaulted fields are marked required in response schemas | The generated client then checks every value a screen reads |
| D76 | A potential decline is summarized by the reading that declines, not by the reading that passed | The brief had shown "California, from the mailing address" as the reason for a potential decline |
| D77 | Display cues the guideline does not set (claim reported more than 14 days after the loss, a quarter's miles down more than 15%) are settings, not rules | They mark rows for attention and never change an outcome |
| D78 | Behavior tests run in a real browser against a perturbation copy of the sample, never the demo submission; a resolution made by the test is reopened before it ends | Tests must not change what the demo shows or its audit trail |
| D79 | A person can correct any field (override) with a reason. The value is read with the field's own kind, stands until cleared even if documents change, reruns the rules, and is audited with before and after | Documents are sometimes wrong or silent (a FEIN given by phone); the correction must be explicit, attributable and reversible, never a silent edit |
| D80 | Every run records an input hash (email and files by content), its versions (steps, ruleset, prompts and models) and a canonical output hash that leaves out ids and timestamps | Makes "same inputs and versions give the same output" checkable rather than claimed |
| D81 | Replay reruns every step, OCR included, against a copy of the database, answers model calls only from the cache (a miss is recorded, never sent), and compares the output hash with what is stored. Only the verdict, the run and an audit event reach the real database | A replay must be free and harmless by construction: a cache miss can never spend money or degrade stored results |
| D82 | A replay under changed versions is reported as a what-if naming the versions, not as a failure | The sandbox submission, last processed before P1's loss-run prompt change, replayed as "differs in facts; extract_loss_run v1 to v2", which is the correct answer |
| D83 | The last rerun (resolve, reopen, correct, undo) is shown above every tab, and the rules tab marks the rules it changed with their old outcome | The effect of a person's decision should follow them, not stay on the screen where they made it |
| D84 | Audit events carry a kind (people, security, model, system) and a plain sentence built by the API; values of personal-data fields in resolution payloads are masked by their attribute | The timeline is read by people; a resolved license number must not leak through a neutral payload key |
| D85 | Perturbations 3, 4 and 9 complete the nine planned perturbations: blurred and JPEG-compressed IFTA scans, a phone photo of the quote form (perspective, shadow, blur), and the FEIN added to the email body. Each expectation was written before its first run; two new checks say a rule reached an outcome and a file was flagged as low quality | All nine pass: blur and the photo are flagged and change no outcome; the FEIN in the email makes APP-01 pass and removes the missing item |
| D86 | A07 revised, ruleset 1.1.0: rules that need data a submission never carries (ELIG-06 SAFER, SEL-01 premium) are `external`. Their unknown is listed as a check at quote on the decision and the brief and does not by itself refer. Any other unknown still refers. Every stored submission was re-decided; only the clean synthetic packet changed, to "Ready for Small Fleet underwriting review" | The first reading made every submission refer, so "ready" could never be reached and the route carried no information |
| D87 | `make eval` scores the gold set, then all perturbations and the synthetic packet from stored runs, and writes the reports the Evals screen reads. `make perturb` builds the packets and processes new ones | One command for the whole measurement, with no model calls unless something new needs processing |
| D88 | Email intake through Mailpit (Tier 2): a poller reads Mailpit's REST API with the standard library, ingests each unread message like an upload (idempotent by Message-ID), starts processing new ones and marks them read. It runs with the API when LANE_MAILPIT_URL is set, or as `make mailpit-watch`; Mailpit being down is logged and retried | Agents email submissions; the demo receives them over real SMTP. Production uses SES or Graph inbound mail to a queue |
| D89 | A person can label a document the classifier could not place or got wrong, with a reason. Labels are kept by stable document id and applied on every classification run until removed; labelling reprocesses the submission so the document is read as its type | Unknown documents are shown for manual labelling and can be relabelled and rerun |
| D90 | The brief shows a banner when a step's latest result was degraded or failed, naming the steps and saying the rest stands; each step's most recent result counts, so a later rules-only rerun cannot hide an extraction that did not finish | Model errors are visible states. Railway deploy (Tier 3, optional) was cut, first in the cut order |
| D91 | The route sign names the external checks still open, on the brief ("2 checks at quote: SAFER record, premium per unit") and in the header when the route is ready ("2 checks at quote"). Short names live in the ruleset (`check:`) and reach the UI with the route | Review of D86: "Ready" must never read as fully cleared while a decline-capable SAFER check is still open. In production SAFER is looked up by USDOT before routing and stops being external |
| D92 | Scans and photos are prepared before they are read: turned upright (geometry decides sideways, OCR reading decides which way up), straightened past 0.5°, flattened when a page outline is found in a photo, and evened out under a smooth shadow; OCR reads a contrast-tuned, enlarged copy. Each step is recorded in words, the original is kept and viewable, and boxes refer to the prepared page. Digital pages and scans with their own text layer are never changed | Triage measured problems but never fixed them. Prep only acts when it is sure: the first shadow method washed out a license portrait, so light is now estimated at shadow scale and photos are left alone (triage version 5) |
| D93 | Known layouts are recognised before any model: templates are data (landmarks in page regions, printed form identifiers, worksheet headers) with field patterns for subject, period and date. A complete match the keywords do not dispute types the page with no model call; a missing required field, a keyword objection or an audit sample sends it to the model, and a disagreement keeps the layout's type and goes to review | Cheaper, faster, deterministic and explainable: the landmarks are drawn on the page. On the sample, 31 of 33 pages are typed by layout; the two license-card photos go to the AI |
| D94 | Templates are proposed from documents a person confirmed (labels, never values), curated by hand, and checked against every stored page before use (make templates-check): a template that matches a page of another type is not used. Production adds a template only after review, and samples template pages for model audit continuously (templates_audit_rate) | All 17 shipped templates are precise across about 450 stored pages; the model agreed on all 31 audited pages of the sample; none matches the synthetic packet's unseen layouts |
| D95 | Eval reports layout coverage and audit agreement, and can score a what-if with templates off on a database copy, cache only.
